# EDDIE 캐릭터 확정 — 에셋 핸드오프 시트

> 캐릭터를 공식 확정할 때 이 한 장만 보면 됨. 자세/사이즈, 부위별 항목, 현재 에셋
> 최적화 상태를 정리. 스타일·색은 `docs/EDDIE-character-spec.md`, 제작 절차는
> `docs/EDDIE-rig-quickstart.md` 참고.
>
> 모든 최종 파일은 **투명 PNG로 렌더 → `public/brand/...` 저장 → `npm run assets`**
> 하면 자동으로 알맞은 해상도 **WebP**로 변환된다(원본 PNG 교체).

---

## 1. 기준(마스터) 캐릭터 — 자세 & 사이즈

**마스터 1장**이 모든 에셋의 출발점. 아래 규격으로 1장 확정:

| 항목 | 값 |
|---|---|
| 자세 | **정면 전신 · 좌우 대칭 · idle(차렷에서 팔만 살짝 띄움)** |
| 캔버스 | **1024 × 1024 정사각** |
| 배경 | **투명**(렌더 시), 또는 단색(마젠타) 후 제거 |
| 정렬 | 캐릭터 **정중앙**, **발끝 하단 ≈ 92%**, 머리 위 안테나 여백 확보 |
| 조명 | 균일 소프트 스튜디오광, **바닥 그림자는 약한 접지 그림자만** |
| 비율 | 치비 2.5등신(머리 큼) — 스펙 문서 기준 |

> 리깅(퍼펫)까지 하려면 **T-포즈(양팔 수평으로 벌린)** 변형 1장을 추가로 받으면
> 부위 분리가 훨씬 쉬움(겨드랑이 빈 공간 확보).

이 마스터는 → `eddie-hero` / `idle` / `dir/down` 의 공통 소스가 된다.

---

## 2. 코드가 찾는 부위별 항목 & 사이즈

전부 **투명 배경**. 폴더 `public/brand/eddie/`. (없으면 코드가 자동 폴백 → 깨지지 않음)

### A. 퍼펫 리그 5부위 (최우선 — 모든 페이지 가이드 에디가 살아 움직임)
같은 **1024×1024 캔버스 안에서 부위만 분리**(제자리, 카메라 고정). 화면 표시 최대 ~520px → 1024는 2배 여유.

| 파일 | 내용 | 사이즈 |
|---|---|---|
| `eddie/rig/body.webp`    | 몸통+다리 | 1024×1024 |
| `eddie/rig/head.webp`    | 머리(TV+눈) | 1024×1024 |
| `eddie/rig/arm-l.webp`   | 화면 왼팔 | 1024×1024 |
| `eddie/rig/arm-r.webp`   | 화면 오른팔 | 1024×1024 |
| `eddie/rig/antenna.webp` | 안테나 | 1024×1024 |
| (회전축) | head 50%/46% · 어깨 40·60%/44% · 안테나 50%/22% | CSS 기반 |

### B. 풀바디 포즈 3종 (리그 없을 때 폴백·병행)
같은 카메라·프레임이라야 크로스페이드가 안 튐.

| 파일 | 내용 | 사이즈 |
|---|---|---|
| `eddie/idle.webp`  | 기본 idle | 1024×1024 |
| `eddie/wave.webp`  | 손 흔들기 | 1024×1024 |
| `eddie/cheer.webp` | 만세/응원 | 1024×1024 |

### C. 탑다운 4방향 워크 (맵 이동 — 현재 비어 있음)
**위에서 본 3/4 탑다운 시점**. 화면 표시 ~115×126px(playerScale 최대 1.75) → 2배+여유로 512.

| 파일 | 시점 | 사이즈 |
|---|---|---|
| `eddie/dir/down.webp`  | 정면(아래로 걷기) | 512×512 |
| `eddie/dir/up.webp`    | 뒷모습 | 512×512 |
| `eddie/dir/left.webp`  | 좌측 | 512×512 |
| `eddie/dir/right.webp` | 우측 | 512×512 |
| (공통) | 발끝 하단, 투명 | — |

### D. 기본 히어로 (dir 없을 때 폴백) & 방별 코스튬
단일 1장. 정면 전신, 발끝 하단. 화면 표시 높이 ~147px → 1024로 충분.

| 파일 | 용도 | 사이즈 |
|---|---|---|
| `eddie/eddie-hero.webp` | 탑다운 기본/UI 폴백 | 1024×1024(또는 768×1024) |
| `eddie-<센서>.webp` (예: `eddie-rgb.webp`) | 방별 코스튬, config `eddie:` 1줄 | 동일 |

> 코스튬은 **히어로 포즈/프레임 그대로 + 악세서리만** 추가해야 "같은 에디"로 보임.

## 3. 현재 이미지 최적화 상태 — 개선/압축 리스트

**현재 `public/brand` = 26개 · 총 2.28MB (이미 전부 WebP 최적화 완료).**
규칙: 배경 2048px · 캐릭터 1024px / WebP q82~86. → **압축은 사실상 끝난 상태**, 추가 작업 거의 불필요.

### 🔴 교체 대상 — 새 캐릭터 확정 시 갈아끼울 이미지 (구 스타일)
| 파일 | 현재 | 처리 |
|---|---|---|
| `eddie/eddie-hero.webp` | 1024² 64KB | 새 마스터로 **교체** |
| `eddie/idle.webp` | 1024² 60KB | 새 포즈로 **교체** |
| `eddie/wave.webp` | 1024² 61KB | 새 포즈로 **교체** |
| `eddie/cheer.webp` | 1024² 64KB | 새 포즈로 **교체** |
| `eddie-conductor.webp` | 1024×1280 84KB | 새 스타일로 **재생성**(LED 게임용) |
| `eddie-buzzer.webp` | 512×768 53KB | 새 스타일 코스튬으로 **재생성** |
| `eddie-buzzer-sing.webp` | 512×640 51KB | 동일 |

> 이건 **압축 문제가 아니라 "구 디자인 → 신 디자인" 교체**. 새 캐릭터 나오면 일괄 교체.

### 🟡 신규 필요 — 현재 없음(폴백 중), 새 캐릭터로 채우기
- `eddie/rig/` 5부위 · `eddie/dir/` 4방향 (위 2-A, 2-C)
- RGB 방 아트: `room-rgb-bg` · `stage-rgb-bg` · `game-rgb-cover` · (선택)`eddie-rgb`

### 🟢 압축 관점 — 그대로 둬도 OK (가장 무거운 것만 참고)
| 파일 | 크기 | 비고 |
|---|---|---|
| `main-bg.webp` | 238KB | 가장 큼이나 메인 1회 로드 — 허용 |
| `stage-buzzer-bg.webp` | 195KB | 무대 배경 — 허용 |
| `hub-bg.webp` | 170KB | 허용 |
| 나머지 | ≤160KB | 양호 |

> 더 줄이려면 배경 캡을 1600px로 낮추거나 q를 78로 — 단, 지금도 충분히 가벼워서
> **굳이 안 해도 됨**. 새 에셋도 `npm run assets`가 자동 처리.

---

## 4. 새 에셋 추가 명령(반복)
```
# (PNG들을 public/brand/... 에 저장한 뒤)
npm run assets      # 리사이즈 + WebP 변환
npm run build       # 확인
git add public/brand && git commit -m "..." && git push
```
